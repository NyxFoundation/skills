# 司会台本と登壇者ページを分ける

同じ台本から 2 つ作る。**混ぜると事故る。**

| | 司会台本 | 登壇者ページ |
|---|---|---|
| 置き場所 | repo の `.md` | Notion / 共有ドキュメント |
| 読む人 | 当日その場で読む司会 | 登壇者（事前に） |
| 読み上げ文 | ある | ある（同じもの） |
| 準備メモ | **`<details>` に畳んで入れる** | **入れない** |
| 時間配分 | 秒単位 | 分単位の表で十分 |

---

## なぜ準備メモを出さないか

準備メモには、書くべきだが公開できないことが入る。実例。

```
- ★この論点は、こちらが相手企業に提案している共同研究そのもの。
  モデレーターが提案側なら、自社提案の宣伝に聞こえない出し方をすること。
  「うちがやります」ではなく「ここが空いています」で止める

- 磯野さんは上場企業の、しかも証券。「御社では」と聞くと答えられない領域に入る。
  業界一般の制約として聞く形にしてある

- 河野さんの答えが「技術です」なら、この回の仮説が否定されたことになる。それが山場

- 万一たくさん手が挙がったら「おお、これは今日いちばんの驚きです」でそのまま進む。動揺しない
```

**どれも正しい準備メモで、どれも本人に見せるものではない。**
1 つめは自社の利害、2 つめは相手の立場に関する判断、3 つめは相手の答えを予測して構えていること、
4 つめは進行の裏。

**この分離を忘れると、既存の共有ページに台本を貼った瞬間に全部流出する。**
共有済みのページを書き換えるときは、**誰が読むページかを先に確認する。**
宛名（「◯◯様」）が入っていたら、それは登壇者ページ。

## 登壇者ページに代わりに入れるもの

準備メモを外したぶん、**確認してほしいことを入れる。**これは相手にとっても有益。

```
<callout icon="✍️">
  **この紹介文で問題ないか、ご確認ください。**
  当日、この文をそのまま読み上げます。肩書き・ご経歴の表現に誤りがあればお知らせください。
</callout>
```

```
<callout icon="🛡️">
  **◯◯様へ。**御社の内部方針をお答えいただく形にはしていません。
  **業界一般の制約としてお答えいただける範囲で結構です。**
  踏み込みすぎている箇所があれば、事前にお知らせください。
</callout>
```

ページ末尾には必ず。

- **お答えにくい質問はありませんか。**触れられない領域があれば事前に教えてください。当日その話題を振りません
- 数字に触れる設計になっている場合は、**出せるものを事前に決めておいてもらう**
- ご紹介の文面の誤りの申告
- 当日使う資料の有無

## 既存のブリーフがあるとき

**消さない。**トグルに畳んで残す。

```
<details>
<summary>従来のセッションブリーフ（2026-08-27 版）</summary>
	**この下は、以前お送りしたブリーフです。**当日の進行は上の台本のほうが新しい版になります。
	セッション時間も 45〜60 分から 40 分に変わりました。テーマの背景としてお読みください。
	（以下、旧版をそのまま）
</details>
```

理由は 2 つ。**登壇者は旧版を読んで返事をしている**ので、突然消えると何が変わったか分からない。
そして**旧版にしかない背景情報**（テーマを置いた理由、参考資料）が、たいてい残っている。

**変わったことは冒頭で明示する。**構成変更・時間変更・登壇者の入れ替わりは、
気づかないまま当日を迎えると事故になる。

```
<callout icon="🔀">
  **構成が変わりました。**◯◯様は新設した英語セッションへお移りいただき、
  担当も △△ 様に変わっています。本セッションは日本語で、3 名でお願いします。
  あわせて、当日の同時通訳は行わず、正面スクリーンに日英の字幕を出す方式に変更しています。
</callout>
```

## Notion に書くときの注意

- **トグルの子要素はタブで字下げする。**しないとトグルの外に出る
- 表をトグルに入れるときは `<table>` の開始・終了行を字下げする
- **`update_content` の部分置換は落ちやすい。**とくに次の 3 つで一致しなくなる。
  - **`<br>` を含む文字列。**送った `<br>` と、Notion が保存した表記が一致しない。
    **`<br>` をまたぐ `old_str` は使わない**
  - 送信時に正規化された空白・記号
  - **1 回の呼び出しで複数の更新を送ると、1 つでも外すと全部落ちる。**
    どれが適用されたか分からなくなるので、**1 件ずつ送るか、`replace_content` にする**
- **迷ったら `replace_content` で全体を置き直す。**トグルの旧版も再送することになるが、
  結果が決まる。部分置換のリトライを重ねるより速い
- **`old_str` は自分で打たない。**fetch した本文からコピーする。
  日本語の氏名はコードポイントを 1 つ間違えると別の字になり（樋 U+6A0B → 梓 U+6893）、
  「ページ側が壊れている」と誤診する。**実際にそれをやった**
- 共有済みページを書き換える前に、**必ず fetch して現在の内容を保存する**

## DB の整合

セッション DB を使っているなら、**ページ本文だけ直して DB のプロパティを放置しない。**

実際に起きたずれ。

- 登壇者欄に、別セッションへ移動した人が残っていた
- 移動してきた人が登壇者欄に入っていなかった
- No. が当日の並び順とずれていた（廃止したセッションの番号が飛んでいた）
- 日本語サブが統合前のままだった

**プロパティを更新したら、必ず読み返して確認する。**日本語の氏名は、
コードポイントを 1 つ間違えると別の字になる（樋口 → 梓口）。
