# 再帰的外部レビュー

書いた台本は成果物ではない。**書いていないエージェントが殺しに来て、生き残ったものが成果物。**
3〜4 ラウンド。**ラウンド数ではなく、指摘の種類で打ち切る。**

---

## 3 視点で回す

台本のレビューは、1 つのプロンプトで全部聞くと指摘が混ざって収束しない。**視点を分ける。**

| 視点 | 何になりきらせるか | 見つかるもの |
|---|---|---|
| **登壇者** | 事前にこの台本を渡された当人 | 答えると自社に不利な質問、法務が止める質問、前提が誤っている質問、紹介文の失礼 |
| **参加者** | 客席の 1 人（職掌の比率を指定する） | 退屈する箇所、内輪語、持ち帰りの不在、通しで飽きる箇所 |
| **進行** | 当日その台本を読む司会 | 時間配分の破綻、声に出して不自然な日本語、字幕に向かない文 |

**登壇者視点がいちばん実りが多い。**答えられない質問は、書いている側からは絶対に見えない。

---

## 反鈍化ラウンド — これを入れないと台本が死ぬ

**汎用のレビュアーは、質問を安全側に倒し続ける。**

「答えられない質問がある」と指摘され、それを直すと、次のラウンドでは
「一般論に流れる」と指摘される。**放置すると、当たり障りのない台本が「合格」になる。**

だから **2 巡目以降に必ず 1 ラウンド、鈍化だけを見るラウンドを入れる。**

```
これは 2 巡目です。1 巡目で「登壇者が答えられない」「事実誤認」「時間が合わない」を直しました。
今回は次の 2 点を最優先で見てください。

【A. 鈍っていないか（最重要）】
発注者の要求は「一般論に流れない、その会社の取り組みを引き出す、具体的で critical な質問」です。
1 巡目の修正で**当たり障りのない質問に後退した箇所**があれば、それが最大の欠陥です。
- 誰に聞いても同じ答えが返る質問はどれか
- 答えが「場合によります」で終わる質問はどれか
- **もっと踏み込めるのに遠慮している質問はどれか。踏み込んだ版を書いてください**

【B. 残っている実務上の欠陥】
まだ答えられない質問、事実誤認、時間の破綻、字幕に向かない長文
```

**A を先に書く。**順番を逆にすると、レビュアーは B から答えて A を薄く扱う。

## 指摘の分類

**指摘は自動的に正しくない。**分類してから直す。

| 種別 | 対応 |
|---|---|
| **正しい** | 直す |
| **診断は正しいが処方が違う** | 根本を自分のやり方で直し、乖離を記録 |
| **鈍化させる提案** | **採らない。**切り分けて、鋭さを保ったまま答えられる形にする |
| **依頼者の明示的な指示と衝突** | 従わない。懸念は別の方法で満たし、指摘と却下理由の両方を報告 |
| **範囲外**（文体の好み、さらなる精緻化） | 却下。次のプロンプトを締める |

3 番目が、この種のレビューに固有の分類。実例。

> **指摘**：「JPYC で誤送金は取り消せますか／損失は誰が持ちますか」は、個別の運用・契約・
> 責任分担を即答させる質問。電子決済手段の発行と償還は登録制度と関わるため技術論として扱えない。
> **提案**：「公開可能な一般論として教えてください」
>
> **判断**：診断は正しい。処方は採らない。「一般論として」を付けると質問が死ぬ。
> **3 つに割った**：「技術としてできること、規約としてできること、利用者が負う範囲。
> この 3 つはいまどう分かれていますか」。答えられる形になり、しかも
> **どこが空いているかがそのまま出る。**

## 実際に効いた指摘

回数を重ねても最後まで出てくるのは、この 5 種類。**先に潰しておく。**

### 1. 受けが無い（最重大）

質問して、答えが返って、すぐ次の質問。**返ってきた答えを客席の言葉に置き直す動作がゼロ。**
専門語が説明されないまま流れていく。**置いてけぼりの正体はこれ。**

### 2. 地ならしが無い

セッションの背景——いま世の中で何が起きていて、なぜこの話をするのか——が無い。
**詳しい人しか付いてこない。**客席には必ず「キャッチアップしたいが市場が掴めていない」人がいる。

### 3. 時間の合計が枠に合わない

見出しに分数を書いていない区間があると、静かに 7〜8 分足りない。
**会場質疑の見出しを書き忘れるのが定番。**機械検査に入れる。

### 4. 事実誤認

規制の年と対象、他業界の仕組みの説明、技術の前提。**声に出すものなので、
登壇者の目の前で露見する。**口に出す数値だけでよいので、一次情報で確認する。

### 5. 受けが第 1 ラウンドにしかない

**セッションに 1 つ書けば満足してしまう。**実際には、第 2・第 3 ラウンドと山場で飛ばしている
ことが多い。**山場に受けが無いのがいちばん惜しい。**
`spoken_check.py` はラウンドごとに見るので、ここは機械で落ちる。

### 6. 受けが「仮説への同意確認」になっている

これは巧妙で、機械では取れない。

```
✗ > 止まったのは ◯◯ だった。技術ではなく。
```

**登壇者が「技術です」と答えても、司会が「技術ではなく」と結論している。**
仮説を検証する場が、仮説に同意させる場に変わっている。

```
✓ > いま、止まった場所に名前が付きました。◯◯ です。
  > 動かなかったのではなく、◯◯ が決まっていなかった。
```

**受けは、答えを客席の言葉に置き直す動作。**こちらの結論に寄せる動作ではない。

### 7. 紹介文の失礼と単純化

- リスク評価の専門家を「攻める側」と呼ぶ（攻撃者と同一視される）
- 確認していない経歴を書く（訂正から始まって 1 分損する）
- **役割を取り違える。**通貨の発行者を「お金を出す側」と紹介した。
  実際にはクライアント・売り手・仲介者で役割が分かれていて、発行者は払う側ではない。
  **紹介文の 1 行が、そのまま前提の誤りになる**
- **提出した講演タイトルを紹介の軸にする。**本人の職責ではなく「この回の看板」として
  扱う形になる

## 実行

```bash
# 台本が長いとプロンプトが大きくなりすぎて、無言で終わることがある。
# セッション単位に割って並列で回す。
for f in s1 s2 s3 s4; do
  nohup codex exec --skip-git-repo-check --sandbox read-only \
    "$(cat prompt_$f.txt)" > review_$f.out 2>&1 &
done
```

- **1 プロンプトを 20KB 以下に割る。**これを超えると、`codex exec` は**プロンプトを
  読み上げただけで、指摘を 1 件も出さずに exit 0 で終わる。**エラーにならないので気づきにくい。
  48KB で 2 回、22KB で 1 回それをやられた。**セッション 1〜2 本ぶんが上限**と思っておく
- **`--sandbox read-only` ではファイルに書けない。**「レビュー結果を X に書き込め」と指示すると、
  書けないまま途中で終わる。**標準出力に出させる**
- 台本本文はプロンプトに**インラインで入れる。**ファイルを読ませると、読んだ内容を
  そのまま出力に転記してくることがある
- 「対象の内容を出力に転記しないこと。引用は 1 件 20 字まで」を明記する
- **完了は `tokens used` の有無で見る。**プロセスの終了だけでは、無言終了と区別できない

```bash
# 全部終わるまで待つ
until [ "$(grep -l 'tokens used' q_*.out 2>/dev/null | wc -l)" -ge 4 ]; do sleep 10; done
```

- **web 検索を始めると 10〜15 分かかる。**事実確認をさせるなら、その時間を見込む

## 収束

```
R1  3 視点 × 5 本並列 — 38 件
    → 答えられない質問 7 / 事実誤認 2 / 時間の破綻 4 / 紹介文の失礼 3 / 持ち帰り無し 6
R2  反鈍化ラウンド — 10 件
    → 鈍化 6（1 巡目の修正で薄まった質問）/ 事実誤認 2（こちらが新たに入れた）/ 進行 2
R3  最終 — 実害のある問題：なし
```

**R2 でこちらが入れた事実誤認が 2 件見つかったのが、このループの価値。**
1 巡目の修正作業そのものが新しい誤りを持ち込む。

打ち切りの合図は、指摘が**「もっと詳しく定義すべき」の水準に移ったとき。**
最終ラウンドのプロンプトに、何を挙げないかを列挙する。

```
次は挙げないでください。
- 改善提案、網羅性、文体の好み
- 「定義を追加すべき」「明記したほうがよい」という類
挙げるのは、当日読み上げたときに実害が出る箇所だけです。
```

## 報告

ラウンド数、判定、**採らなかった指摘とその理由**を依頼者に伝える。
とくに**鈍化させる提案を却下したこと**は必ず言う。
黙って採ると、依頼者は「なぜ質問が薄くなったのか」が分からないまま受け取ることになる。
