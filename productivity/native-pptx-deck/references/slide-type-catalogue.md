# スライドの型カタログ（収集したもの）

外部の分類を集めて並べたもの。**思いつきで図を描かないための在庫表**。
原則と禁則は `layout-patterns.md`、ここは「どんな型が世の中にあるか」だけを持つ。

集めた総数 **69 型**（重複あり）。出典は各節の末尾。

---

## 0. 引き方

上から順に降りると、図の種類は機械的に決まる。

```
1. この枚は何の問いに答えるか          → Roam の 6W（§2）
2. 数字を見せるなら、どの比較か        → Zelazny の 5 比較（§3）
3. 数字でないなら、情報どうしの関係は   → Duarte の 5 系統（§1）
4. 版面はどれか                       → layout-patterns.md §4（A〜K）
```

2 と 3 は排他ではない。両方が同じ図を指したら、それが正解。
指すものが割れたら、**1 の問いに戻る**。たいてい 1 枚に 2 つ質問が入っている。

## 1. Duarte ── 情報どうしの関係（5 系統・14 下位型）

Nancy Duarte が自社デザイナーのスケッチ数千点を分類して得たもの。
**情報どうしの関係はこの 5 つのどれかに落ちる**という主張で、実物は約 4,000 図。
`Slide:ology` 第 3 章が初出、Diagrammer で下位型まで整理されている。

| 系統 | 定義（Diagrammer の言い方） | 下位型 |
|---|---|---|
| **Flow** | 図形が同じ向きに流れ、交差しない | Linear（直線）／ Loop（循環）／ Merge–Divide（合流・分岐）／ Parallel（並走） |
| **Network** | 図形どうしのつながり方を見せる | Hub and Spokes（中心と放射）／ Spokes（放射のみ）／ Ring（環）／ Flare（末広がり） |
| **Stack** | 図形を積む | Vertical（縦積み＝層）／ Horizontal（横積み＝並置） |
| **Segment** | 全体を切り分ける。中心に穴やハブを持つ | Pie（扇）／ Donut（環） |
| **Join** | 引っかかって組み合う | Hook（噛み合い）／ Overlap（重なり） |

この判型での実装メモ:

- **Flow–Linear** がいちばん潰しが効く。主体を並べ、edge に動詞を置く（`layout-patterns.md` §4.5 構成図）
- **Flow–Loop** は横一列＋下に戻り矢印で描く。本当の円環にすると小さくなって読めない
- **Stack–Vertical** は「どの層の話か」を 1 層だけ着色する
- **Segment** は Pie/Donut ではなく **100% 横バー**にする（角度より長さのほうが正確に読める）
- **Network** は節点 5 つまで。超えたら Stack か Segment に読み替えられないか疑う
- **Join–Overlap** はベン図。2 円まで、3 円にすると領域のラベルが置けない

出典：[Duarte Diagrammer](https://diagrammer.duarte.com/)、
[Duarte ブログ](https://www.duarte.com/blog/duarte-diagrammer-thousands-of-free-diagrams-at-your-fingertips/)

## 2. Roam ── 問いから図を決める（6 型）

`The Back of the Napkin`。「その枚が答えている問い」で図の種類が決まる。
**図を描く前に、まずこの表で問いを 1 つに絞る。**

| 問い | 図 | この判型での既定形 |
|---|---|---|
| 誰が・何が | 肖像（対象そのもの） | 写真・スクリーンショット・製品図 |
| どれだけ | チャート | §3 へ降りる |
| どこで | 地図・配置図 | 構成図（どの主体の中で起きるか） |
| いつ | タイムライン | 横線に印 3 つまで |
| どうやって | フローチャート | Flow–Linear の構成図 |
| なぜ | 多変数プロット | 2 軸マトリクス（§5 の 2×2） |

出典：Dan Roam『The Back of the Napkin』（6W × 6 図の対応）

## 3. Zelazny ── 数字の見せ方（5 比較）

`Say It With Charts`。**言いたいことが決まると、チャートの種類は機械的に決まる。**
順序が逆（先にチャートを選ぶ）だと必ず失敗する。

| 比較 | 引き金になる言葉 | チャート |
|---|---|---|
| **構成比** component | 全体の◯%、シェア、内訳 | 円 → **この判型では 100% 横バー** |
| **項目比較** item | より大きい／小さい、順位、上位◯件 | 横棒（バー） |
| **時系列** time series | 変化した、伸びた、落ちた、推移 | 縦棒（点が 6〜8 まで）／ 折れ線（多いとき） |
| **度数分布** frequency | ◯〜◯の範囲、集中、分布 | ヒストグラム（縦棒）／ 折れ線 |
| **相関** correlation | ◯に伴って、◯するほど、関係する | 散布図／対バー |

- 縦棒は**水準**を、折れ線は**傾き**を強調する。同じ時系列でも言いたいことで選び分ける
- 5 つのどれにも当てはまらないなら、それは数字の話ではない。§1 か §2 に戻る

出典：Gene Zelazny『Say It With Charts』（5 比較 → チャート形式の対応と引き金語）

## 4. SmartArt ── PowerPoint が持っている分類（8 種）

自分で描く前に、既にアプリ側が持っている分類。**名前の付け方の参考**として持っておく。
（SmartArt そのものは使わない。テーマ依存の影と配色が入り、この設計と合わない）

| 種別 | 何のためか |
|---|---|
| List | 順序のない情報 |
| Process | 順序と終点のある手順 |
| Cycle | 終わらずに回り続ける過程 |
| Hierarchy | 組織図・決定木・上下関係 |
| Relationship | 順序も上下も無い関係。重なり、ベン図、中心への接続 |
| Matrix | 全体に対する部分の位置。2 次元の分類 |
| Pyramid | 比率的・階層的で、積み上がるもの |
| Picture | 写真が主役で、文字は添え物 |

出典：[Microsoft — Choose a SmartArt graphic](https://support.microsoft.com/en-us/office/choose-a-smartart-graphic-e9a7a134-f8a5-4251-aba2-93f96b88644d)

## 5. コンサル系デッキの定番枚（14 型）

戦略ファームのデッキで繰り返し出てくる枚。**毎回設計し直さない**ためのリスト。

| 型 | 何をする枚か | 決まりごと |
|---|---|---|
| **大きな数字** | 1 つの指標で語る | 数字の下に文脈を 1 行。`layout-patterns.md` F |
| **縦棒チャート** | 既定のチャート。比較・時系列・分布・順位 | 見出しはデータの**解釈** |
| **チャート＋示唆** | 図が 2/3、右 1/3 に示唆 | 示唆から図の該当箇所へ引き出し線 |
| **2 列比較** | before/after、案 A と案 B | **両列の構造を揃える**。揃わないなら比較になっていない |
| **3 つの柱** | 並列な 3 点＋アイコン | 3 が上限 |
| **プロセスフロー** | 手順・方法論 | **4〜5 ステップまで**。下に期間と担当 |
| **ウォーターフォール** | 始点から終点への増減の内訳 | 「差をどう埋めるか」に答える枚 |
| **ファネル** | 段階ごとの脱落 | 落ち幅を見せるのが目的 |
| **2×2 / フレーム** | 優先順位づけ | 軸にラベル。判断が客観に見える |
| **ハーベイボール表** | ベンダー・能力の評価 | 数値でなく塗り分け。**偽の精度を避ける** |
| **引用＋証拠** | 左に生の声、右に裏づけ | 定性と定量を 1 枚で |
| **タイムライン** | 実行計画 | 線・節目・上に工程・下にリスクの 3 層 |
| **ダッシュボード** | 指標 4〜6 枚のタイル | どれに注意が要るかを 1 つ強調 |
| **エグゼクティブサマリー** | 全体の主張を 1 枚 | 状況｜発見｜提言 の 3 列（SCR） |

出典：[StrategyU — The 14 Slide Layouts That Consulting Firms Use for Everything](https://strategyu.co/slide-layouts/)、
[Deckary](https://deckary.com/blog/pillar-consulting-presentations-guide)、
[Slideworks（元 MBB による 160 デッキの分解）](https://slideworks.io/resources/47-real-mckinsey-presentations)

## 6. 実装済みの型（22 パターン）

同じことを先にやっている実装。**型の粒度と検査項目の参考**になる。

構造枚：表紙／中扉／裏表紙／アジェンダ／箇条書き／締め／引用
数字枚：ウォーターフォール／ギャップ／before-after／時系列／ベンチマーク表／要約帯
関係枚：プロセスフロー／ファネル／ヒートマップ／ガント／KPI スコアカード／2×2／散布図／分布／スモールマルチプル

検査項目として持っているもの（**そのまま真似できる**）:

- ゼロ基線を明示する
- Lie Factor ≒ 1.0（棒の比が実際の数値の比と一致する）
- 色だけに意味を持たせない
- 文字を黙って切らない（silent truncation の禁止）
- 塗り分けの全域で文字のコントラストが WCAG AA を通る
- 比較の型（構成比／項目／時系列／分布／相関）でパターンを選ばせる

出典：[mckinsey-style-visualization-skill](https://github.com/kgraph57/mckinsey-style-visualization-skill)

## 7. 畳んだ実用リスト

上の 69 型から重複を落とし、**この判型（16:9・投影・和文）で実際に使うもの**だけ残したもの。
迷ったらこの 12 個から選ぶ。

| # | 型 | 元の分類 | 版面 |
|---|---|---|---|
| 1 | **構成図**（主体と行為） | Duarte Flow–Linear ＋ Roam どうやって | C |
| 2 | **循環図** | Duarte Flow–Loop | C |
| 3 | **層** | Duarte Stack–Vertical | C |
| 4 | **100% 横バー** | Duarte Segment ＋ Zelazny 構成比 | C / F |
| 5 | **重なり** | Duarte Join–Overlap | C |
| 6 | **中心と放射** | Duarte Network–Hub | C |
| 7 | **横棒（項目比較）** | Zelazny 項目 | C |
| 8 | **縦棒／折れ線（時系列）** | Zelazny 時系列 | C |
| 9 | **散布図（相関）** | Zelazny 相関 ＋ Roam なぜ | C |
| 10 | **2×2** | コンサル定番 ＋ SmartArt Matrix | C |
| 11 | **タイムライン** | Roam いつ ＋ コンサル定番 | I |
| 12 | **写真・スクショ** | Roam 誰が何が ＋ SmartArt Picture | C / E |

**この 12 に入らない図を描こうとしているときは、いったん止まる。**
たいてい 1 枚に 2 つのことを言おうとしている。

ウォーターフォール・ファネル・ガント・ハーベイボール・ダッシュボードは、
この判型では**まだ要らない**（出番が来たら §5 から引く）。
