# Slide copy rules

Nyx の見出し 1 本ごとのテスト：**その語は、画面の主視覚が示す対象・比較・関係を
そのまま指しているか。** 指していなければ削るか、図を作り直す。

タイトルは、具体的な対象を名付けるか、図が裏付ける発見・示唆を述べる。
言葉遊び、未来像、抽象語だけの煽りは、証拠を持たない AI 的なコピーに見えるので使わない。

---

## 1. 見出しは具体的な体言止め、または示唆のある主張文

Nyx の本文スライドは、**短い体言止め**を基本にする。
「Leanを用いた静的解析ツール」「Yosysを用いた半導体回路設計」のように、
初見の聞き手が道具と対象を把握できる具体語を使う。
メッセージをタイトルにするなら、発見・変化・示唆があり、図がそれを裏付けること。
例えば「全入力の検査で両出力の÷2欠落を発見」は、検査範囲と欠落箇所を図に示す場合に使える。
「制御フローに仕様を重ねる」のように、動詞があっても動作を想像できない文は避ける。
手動版の完全再現を求められた場合は、この既定値でタイトルを書き換えない。

| ✗ | ✓ |
|---|---|
| 証明を使えるものにする話 | 証明の到達範囲 |
| AIの答えを人が検算しなくていい世界に | 人間の確認領域 |
| いま何が起きているのか | 依存関係の全体像 |
| 既存方式はここが弱い | 既存方式との相違 |
| 証明が届くのはモデル上の関係まで。 | 証明の到達範囲と外部前提 |

判定規則：

- **短く・具体語で。** 対象や関係を名付けるか、図から読める発見・示唆を述べる
- 連作なら文型ではなく**命名の粒度**を揃える（例: 「AとBの相違」「Cの到達範囲」）
- 「〜の話」「〜について」「未来」「世界」「本質」「可能性」のように、対象を指定しない語は
  使わない。固有名詞や関係語に置き換える
- カバーと節扉は題名だけでよい。本文スライドに結論文・サブタイトルを足して二段にしない

### 1.1 画面に置くのは図を読むための語だけ

注釈、凡例、出典、但し書きは、**消しても判断が変わらないなら消す**。代わりに、図を
読み違えないためのラベルは対象の隣に残す。画面から落とした背景、補足、運用上の説明は
発表者ノートへ移す。

| 画面に残す | ノートへ移す |
|---|---|
| 数字の単位・母数、到達範囲、比較の軸、図中の対象名 | 図の読み上げ、操作説明、既出事実の言い直し、内部向けの注意 |
| 省くと主張が過大になる限定 | 省いても図の解釈が変わらない背景 |

### 1.2 図を主役にする

主張と視覚的証拠を対応させる Assertion–Evidence の原則を守る。
見出しが体言止めでも主張文でも、作成計画の「要点」を図から読めるようにする。
文字の列が図の代わりになっているなら、タイトルを直す前に図を描き直す。
小さい章番号・ツール名の帯（`03 ／ mulu ・13` 等）は省き、主見出しと図へ視線を集める。
図を言い直すリード文・締めの一行をテンプレートとして足さない。

### 1.3 表の見出しも体言止めの名詞にする ★

**見出しの規則は表頭にも効く。** 表頭に「〜したこと」「何が〜か」「〜はどうだったか」と
書くと、列が何を集めたものか分からないまま読まされる。

| ✗ | ✓ |
|---|---|
| 起きたこと / 何が起きたか / 判定の側はどうだったか | 事例 / 経過 / 認可の判定 |
| どんな影響があるか | 影響範囲 |
| 誰が担当するか | 担当 |

**同じ枚の図にある語を、表頭に再利用する。** 上の例では 3 列目を「認可の判定」にしたことで、
枚の上半分のフロー図にある同名の箱と表がつながり、図と表が同じものを指していることが見える。
無関係な語で名付けると、1 枚に 2 つの語彙が同居する。

**例外は、問いそのものが列の意味になっている表。**
「介入したあと別の物理作用が出るか」のように、**類型を分ける問いを列名にしている**なら
問いのまま残す。名詞に直すと表の趣旨が落ちる。判定は「その列は分類の軸か、集めた属性か」。

## 2. 気取りの検出

「キモい」と言われたときに疑う順番。上から潰す。

| # | 症状 | 直し方 |
|---|---|---|
| 1 | 未来像・詩的な比喩・言葉遊び | 図で示せる対象・関係・数字に置き換える |
| 2 | 日本語の偽斜体 | §3。技術的な原因 |
| 3 | 文語調の混入（〜であろう / 〜に他ならない / 〜たらしめる） | 削除または事実の文に直す |
| 4 | 煽り語（青天井 / 巨大市場 / 本丸 / 希少 / 既成事実 / 覇権） | 数字か条件に置き換える |
| 5 | 先回りの否定（これは単なる〜ではない / SF ではない） | 削除。読者は疑っていない |
| 6 | 「X ではない。Y だ。」型の反転パンチライン | 図中の比較に置き換える |
| 7 | 芝居がかった締め（これが、いま我々が立っている場所だ） | 題・連絡先・必要な次の行動だけ残す |
| 8 | em dash（──）の多用 | 読点か句点に置き換える |
| 9 | 修辞疑問 | 図が答える問いとして作成計画にだけ置く |
| 10 | 太字の乱用 | 色・位置・余白で 1 箇所だけ示す |

## 2.1 締めの一行を全枚で同じ型にしない ★★

図の下に置く**締めの一行**は、1 枚ずつ見ると問題がない。**全枚を縦に並べると匂う。**

### 匂いの正体

**強調構文（〜のは、〜だ）＋ 一文目を二文目で説明し直す couplet。**

```
✗ どれも認可の判定は通っている。止まらなかったのは、判定と作用が別の時点にあるからです。
✓ 3件とも、認可は通ったうえで起きている。

✗ 入れ替わりは、どちらの構成にも等しく起きます。違うのは、それを見る時点があるかどうかです。
✓ 入れ替わりは上下どちらにも起きている。下だけが、作用の直前にもう一度見ている。

✗ 既存の機構を置き換えるのではなく、それらをつなぐ規則を置いた。ここが他の方式との違いです。
✓ どれも置き換えていない。既存の機構のつなぎ方だけを決めている。

✗ 3本とも同じ経路に入ります。通るのは、…ものだけです。
✓ 対象・内容の指紋・権限が承認票と一致し、トークンが未使用。それが揃った1本だけ届く。

✗ …作用の境界で結び直す。それがこの仕組みです。      ← 締めの枚
✓ …作用の境界で結び直す。
```

引き金になる型：**「〜のは…だ」「違うのは…」「ここが…です」「それが…です」「〜ためです」
「優劣ではなく、…です」**。

二文目は図が既に言っているので §6.2 の冗長でもある。ただし §6.2 は**同じ枚の図との重複**を
見る規則で、ここは**枚をまたいだ構文の重複**を見る。別々に鳴るので両方通す。

### 直し方

- 締めは**常体の一文**で言い切る。説明は図と発表者ノートに渡す
- 言い切ると短くなりすぎる気がしても足さない。図の隣では、短いほうが読まれる

### 検査のしかた

**ゲートが検出する。**

```bash
uv run assets/selfcheck.py out/deck.pptx     # [締めの構文] で鳴る
```

3 枚以上で同型が出たら NG を返し、該当する枚の番号を全部並べる。
手で見るなら、**全枚の締めの一行だけを抜いて縦に並べて読む。**
**同じ構文が 3 枚続いたら、そこが直す場所。** 1 枚ずつレビューしても出てこない。

実測：2026-10 の技術説明資料で、依頼者の指摘は
**「どれも認可の判定は通っている。／3本とも同じ経路に入ります。とかもなんかAI臭いんだよなあ」**
の一行だけだった。2 枚しか名指しされていないが、**同じ型は 13 枚中 5 枚に出ていた。**
名指しされた枚だけ直すと、残りが同じ匂いのまま残る。**1 枚指摘されたら全枚を抜いて並べる。**
（指摘を受ける前の版にゲートを当てると、その 5 枚を全部挙げた。直した版では 0 件。）

### 敬体と常体を枚ごとに混ぜない

同じ場所（締めの一行）が、ある枚は「〜です」で別の枚は「〜だ」になっていると、
**書き手が複数いるように読める**。これも AI 臭さとして指摘される。

| 役割 | 文体 |
|---|---|
| 締めの一行・図中のラベル・表のセル | **常体**。短く言い切る |
| 本文の説明・箇条書きの地の文 | 敬体でも常体でもよいが、デッキ内で統一 |
| 免責・断り書き（「特許性の判断は扱いません」） | **敬体のまま残す。**ここだけは硬いほうが効く |

## 3. 日本語に Latin serif の italic を当てない ★

`Cormorant Garamond` などのラテン書体に**日本語グリフは無い**。
italic を指定すると別フォントに落ちて、**日本語に偽斜体がかかる**。
エラーは出ず、レンダリングして初めて分かる。「キモさ」の主要因になりうる。

| ✗ | ✓ |
|---|---|
| `run("入れ替える", font=SERIF, italic=True)` | `run("入れ替える", font=JP, color=ACCENT)` |
| 日本語の強調を斜体で示す | 日本語の強調は**色だけ**で示す（傾けない） |
| 数字も日本語も同じ扱い | 数字・ラテン文字**だけ** italic serif |

```python
def _is_latin(text):
    return all(ord(c) < 0x2E80 for c in text if not c.isspace())

run(p, text,
    font=SERIF if (is_em and _is_latin(text)) else JP,
    color=ACCENT if is_em else INK,
    italic=bool(is_em and _is_latin(text)))
```

`43` `85 : 1` `16,854` のような数字は italic serif が映える。日本語は色だけ。

## 4. 活動記録を事実として書かない

「やった」は事実ではない。**何が分かったか**が事実。

| ✗ | ✓ |
|---|---|
| 8/15、不完備契約のインタビューを実施しました | （何が分かったかを書けないなら**載せない**） |
| 記事構成案が起草されました | （内部活動報告。載せない） |
| 3 つのプロジェクトについて議論しました | 8 月は 3 つのプロジェクトが進みました＋各 1 行の進捗 |
| リサーチを進めています | 174 のリポジトリのコミット履歴を解析しました |

書けないなら落とす。**枠を埋めるために薄い事実を入れない。**

## 5. 出せないものを出さない

元メモの記載を最優先する。判断を上書きしない。

| 元メモの記載 | 扱い |
|---|---|
| 詳細は話せない | 載せない。状態（論文執筆中など）だけなら可 |
| 執筆中 / 未公開 | 中身は載せない |
| 非公開イベント | **参加者リストと原文メールは出さない。**議論された論点だけなら出せる場合がある |
| 新規はあまり募集していない | 「一緒にやりたいこと」に出さない |
| 単著で書き終えたい | 協力の呼びかけに使わない |

未開催の予定を過去形で書かない。実際に「8/13 に会合を開いた」と書いて、
元メモを読み直したら**未開催の非公開イベント**だった事故がある。日付と時制は原典に当たる。

## 6. 数字

| ✗ | ✓ |
|---|---|
| 多数の脆弱性を発見 | セキュリティ修正 16,854 件、うち CVE 未登録 4,349 件 |
| 圧倒的な比率 | 85 : 1 |
| ほとんど見えていない | 番号がついて世に見えているのは 1.2% |

- **比の向きを本文に書く。**「85 : 1」だけでは、どちらが 85 か読み手に伝わらない
- 複数の数字を並べたら、相互の関係が成立しているか確かめる
  （16,854 / 4,349 / 1.2% が同じ母数の話になっているか）
- 出典に当たれない数字は載せない。`[要確認]` のまま出荷しない

### 6.1 大きな数字の受け方 ★

数字を単独で大きく置く枚では、**説明を文で書かない。2 文字の見出し語で受ける。**

```
✗  43
   メンバーが書いた issue の数        ← 図と棒が既に言っている。冗長

✓  合計                              ← mono・小・faint
   43
```

- 文で説明すると、隣の図が言っていることの言い直しになる（実際に「冗長」と指摘された）
- ただし**ラベルを全部消すと、その数が何なのか 10 秒では分からなくなる**。
  ゲートの「数字のラベル」はここで鳴る。**消すのは文、残すのは語**
- 数字の直下は、置き場所（URL・出典）を置くのに最適な場所。
  「N ある → ここにある」と縦に読める

## 6.2 冗長な一行を書かない ★★

**このスキルで最も繰り返し指摘された欠陥。** 説明したくなる衝動を制度で止める。

### 判定規則はひとつ

> **その文を消したとき、失われる情報があるか。無ければ書かない。**

「あったほうが親切」は理由にならない。冗長な一行は、
親切なのではなく**隣にある証拠を格下げしている**。

### 冗長が隠れる 3 か所

**(a) 図・写真の言い直し（同じ枚の中）**

| ✗ 消した文 | どこが既に言っているか |
|---|---|
| 一人ひとりが「これをやりたい」と思っていることを、issue にしてあります。 | issue 一覧のスクリーンショット |
| 43 全部そのまま公開しています。 | 数字「43」と一覧そのもの |
| ✓ 今日はこのうち 7 件を話します。 | **図から読めない。残す**（次の枚への橋） |

**(b) 数字の言い直し（同じ枚の中）**

| ✗ | どこが既に言っているか |
|---|---|
| メンバーが書いた issue の数 | 隣の棒グラフと合計の数字 |
| 9 人が書いています | 並んでいる 9 個の顔 |

→ 残すなら**文ではなく 2 文字の見出し語**（§6.1）。

**(c) 前の枚で言ったことの繰り返し（枚をまたぐ）** ← 見落としやすい

締めの枚で特に起きる。**締めは要約の場ではない。**

| ✗ 締めに書いた文 | どの枚が既に言ったか |
|---|---|
| Nyx Office Hour は毎月開きます。 | 募集の枚の見出し「**毎月** 3 名を…」 |
| 次に何を考えているかは、interests でいつでも見られます。 | 興味の枚で URL に下線まで引いて強調した |

前で立てた主張を締めで繰り返すと、**「さっきも言ったやつ」に格下げされる**。
締めに置いてよいのは、**まだ一度も出していない情報**（連絡先など）だけ。

### 書く前に止める

一行を足そうとしたら、書く前に自問する。

```
1. 隣の図・写真・数字が、これを言っていないか
2. 前の枚が、これを言っていないか
3. 消したら、聞き手が知らないままになる事実があるか
   → 3 が「無い」なら書かない
```

**削るときは全部消さない。** 指示対象まで消すと、数字が何の数か分からなくなる
（ゲートの「数字のラベル」がここで鳴る）。**消すのは文、残すのは語。**

## 7. 場に合わせる

**熱量設計（Narrative Heat Engineering など）は場を選ぶ。**
社内の月次共有、勉強会、「雑に話す場」に持ち込むと作り込みすぎて浮く。
実際に、Office Hour（雑に話す場と明記されている会）向けに NHE で組んだデッキは
**「構成がいまみたけど変すぎる」**と却下された。

| 場 | 構成 |
|---|---|
| 月次共有・進捗報告・勉強会 | **順に理解できる素直な流れ**（下記） |
| ピッチ・資金調達・ビジョン共有 | 熱量設計を使ってよい |
| 提案・審査 | Pyramid Principle（結論 → MECE な根拠） |

素直な流れの型：

```
カバー → 私たちは何者か → 今日話すこと → やっていること
      → 直近の動き → メンバーの興味 → その中身 → 一緒にやれること → 閉じ
```

「今日話すこと」を 3 項目で先に見せると、聞き手が自分の位置を見失わない。

## 8. 本文

- 専門語の隣に、それを使わない言い換えを 1 行置く。**言い換えにも専門語を混ぜない**
  （✗ 「全ノードに効く」「移行コストの試算がない」← どちらも専門語のまま）
- 1 枚 1 メッセージ。2 つ入れたくなったら 2 枚に割る
- 1 枚あたりの事実は 2〜3 件まで。7.5 分で 19 件は消化できない
- 箇条書きの入れ子は作らない

## Pre-flight checklist

レンダリングした PNG を見ながら通す。

```
[ ] 見出しが、具体的な体言止め、または図で裏付けた発見・示唆である
[ ] 見出しの対象・関係・主張が、図から読み取れる
[ ] 「未来 / 世界 / 本質 / 可能性」など、対象を指定しない抽象コピーがゼロ
[ ] 日本語に italic がかかっている箇所がゼロ（PNG を目視）
[ ] 青天井 / 巨大市場 / 本丸 / 希少 / 覇権 がゼロ
[ ] 「これは単なる〜ではない」型の先回り否定がゼロ
[ ] **全枚の締めの一行を縦に並べて読み、同じ構文が 3 枚続いていない（§2.1）**
[ ] 締めの一行に「〜のは…だ / 違うのは… / ここが…です / それが…です」が無い
[ ] 締めの一行の文体（敬体・常体）が全枚で揃っている
[ ] 表頭が体言止めの名詞である（分類の軸として問いを置く列を除く・§1.3）
[ ] em dash（──）が 1 枚に 1 個以下
[ ] 「実施しました」「議論しました」で止まっている記述がゼロ
[ ] 元メモに「話せない」「非公開」とあるものが載っていない
[ ] 未開催の予定を過去形で書いていない
[ ] 数字の比の向きが本文に書かれている
[ ] 図・写真・数字の隣に、それを言い直しただけの文が無い（§6.2a・b）
[ ] 締めの枚に、前の枚で言ったことの繰り返しが無い（§6.2c）
[ ] 注記を一つずつ消して、図の解釈が変わらないものをノートへ移した
[ ] 一行ずつ「消したら失われる情報があるか」を通した
[ ] [要確認] が残っていない、または残っていることを依頼者に伝えた
[ ] 全スライドの PNG を目視した
```
