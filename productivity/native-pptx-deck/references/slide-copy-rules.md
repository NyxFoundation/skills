# 画面に置く言葉を決める

読む場面：見出し・ラベル・添え書きの作成、長文ページの簡素化。
外部原則の出典・適用範囲は[pitch-principles](pitch-principles.md)。ここには実務の判断基準を置く。

## 1. 見出しは、聴き手が持ち帰る具体的な意味

本文スライドでは、誰が・何を・どうしたか、何がいくつ変わったかを先に書く。
「概要」「仕組み」「形式検証の可能性」のような題目だけで済ませない。
表紙・節扉・作品名・製品紹介など、名称自体が意味を持つ場面では短い名詞句でよい。
手修正版の再現を依頼された場合は、文型の既定値で上書きしない。

| 解読を要求する言い方 | 具体的な言い方と必要な裏付け |
|---|---|
| 形式検証の活用 | 残高を超える出金を拒否し、残高が負にならないことを証明する（そのモデルと実検査） |
| AI監査の高度化 | コードの位置と、仕様に反すると考えた根拠を出す（監査候補画面） |
| 侵入後のレジリエンス | 委任した送金権限を、5分ごと0.001 ETHまでに制限する（その設定例） |
| 業界の大きな潮流 | Microsoft ResearchがPDD Kitを発表（公式記事） |

これは使い回す定型文ではない。利用する証拠・数字・会社名に合わせて書き直す。
「と」で別の結論を並べたら、1枚で扱う必要があるか見直す。

### 1.1 画面に置くもの、話すもの

画面に置くのは、**名前、中心となる数字、短い引用、対象を指すラベル、意味を決める限定**。
それだけでは初見で意味が分からない場合は、短い平叙文の要点を添える。

| 画面に残す | 話す内容・配布用の詳細へ |
|---|---|
| 人・会社・製品・対象の名前 | 研究や会社の長い背景 |
| 数字の意味、単位、母数、期間 | 主張の理解に不要な内訳 |
| 「専門家の補助あり」「説明用モデル」等、真偽を変える限定 | 内部の作業手順・編集者向けのメモ |
| 画像や図を読み違えないための直接ラベル | 原文の全文訳や長い読み上げ文 |

発表者ノートを空にする指定がある場合は、説明を別ファイルへ出す。
出典URLはテンプレート・利用者の指定に従い、巻末やノート等へ置く。省略しても発行元の識別や重要な限定は失わせない。

### 1.2 主張と証拠を一致させる

- 見出しが「AIと形式検証の併用」なのに、画像が「投資発表」のタイトルだけなら不十分。該当の概要・本文も示すか、見出しを証拠の範囲へ狭める。
- 意味を伝えるための日本語の要点は、英語記事と並べてよい。理解を助ける一文まで「冗長」として削らない。
- 見出しから、主視覚の中のどこを見れば根拠があるか指せるようにする。
- 「〜の図」「〜の画面」を置くこと自体を成果にしない。何が分かる画像なのか決める。

### 1.3 表頭とラベル

比較軸は「対象」「期間」「確認結果」等、何を集めた列か分かる名前にする。
問いそのものが分類軸なら、問いのままでもよい。同じものを枚ごとに別名で呼ばない。
略語は初出で必要最小限だけ開き、分かりやすさのために架空の専門語を新設しない。

## 2. 短さより、具体性と読みやすさ

Seibelの利用者の動作による説明、Grahamの普通の語・単純な文を応用する。

- 「何を入れると、何が出るか」「設定を変えると、何が止まるか」で説明する。
- 「高度化」「価値創出」「未来を変える」を、対象・動作・観測値へ置き換える。
- 箇条書きの入れ子や、説明のためだけの説明を避ける。
- 決めた文字数に収めるために、主語・単位・条件を消さない。足りなければページを分ける。
- 名前・引用・指定タイトルを、編集上の語彙規則で改変しない。

### 2.1 同じ言い回しを繰り返さない

見出しだけ、添え書きだけを縦に並べて読む。「違うのは」「これが〜だ」「〜ではない。〜だ」が続いていれば、具体的な内容へ戻して書き直す。
全枚に締めの一行を足す必要はない。文体は同じ役割でそろえる。語句の出現だけで機械的に失格にせず、引用・意図的な比較・利用者の指定を考慮する。

## 3. 見た目のコピーを、技術で壊さない

- 日本語を持たないラテン書体のitalicで日本語を偽斜体にしない。
- 文字を小さくして長文を押し込まない。投影で重要な要点は大きく、上方へ置く。
- 会社名・人物名・数字の綴りを、原資料で照合する。OCRの推測を確定情報にしない。

## 4. 活動・結果・予定を分ける

進捗共有では活動そのものが必要なこともあるが、結果が主題なら「実施しました」で止めず、何が分かったかまで示す。
まだ結果がないときは未確認・検討中という状態を保つ。予定を過去形にせず、結果を作らない。

## 5. 証拠の強さを変えない

- 記事の発表、導入事例、実測結果、自分の提案を区別する。
- 監査の候補を確定脆弱性に、再評価を新規発見に、テスト例を全入力の保証に変えない。
- 実施例の写真に、自分が提案する保存期間・担当分担の実績を負わせない。「運用例」等を明示する。
- 元メモの非公開指定を保つ。未公開の詳細や会議の原文を、説得力のために追加しない。

## 6. 数字は、主張の意味と一緒に置く

中心となる数字を絞り、何の数量か・比の向き・単位・母数・期間を近くへ置く。
比較に必要な複数の値は残す。割合と件数、到達した環境と侵害成功、上限と観測値を区別する。
出典が確認できない数字を、強い言い切りで埋めない。

### 6.1 大きな数字のラベル

「15/15」だけでは、何を数えたか分からない。「既知・対象内の欠陥／専門家の補助あり」まで読むと意味が決まる。
二文字のラベルで足りる場合も、短い句が必要な場合もある。ラベルの文字数を固定しない。

### 6.2 不要な一行を削る

消すと意味・判断・行動のどれかが失われるかを確かめる。

- (a) 主視覚が既に伝える内容を、そのままもう一度書くだけなら削る。
- (b) 数字の対象・比較の軸まで消すと誤読するなら残す。
- (c) 前ページと同じ説明を惰性で反復しない。ただし、長い講演の再定位や依頼されたまとめは、聴き手の必要に応じて行う。

## 7. 場と目的に合わせる

講演・教育では、具体例を追って理解できる流れにする。ピッチでは事業の価値と根拠、提案では相手の判断に必要な事実を優先する。
資金調達のテンプレートや煽りの文体を、社内共有や技術講演へ一律に適用しない。

## 8. コピーの確認

1. 見出しだけを順に読み、内容と流れが分かるか。
2. 知らない人が自分の言葉で言い直せるか。補足説明がないと分からない箇所はどこか。
3. 普通の語と具体的な動作で書けているか。
4. 主張を支える実物があり、重要な条件が残っているか。
5. 一文を削っても意味が変わらなければ削ったか。必要な日本語の要点まで削っていないか。
