# 手動編集したスライドを生成元へ戻す

「この版と全く同じスライドを再生成」「スクリプトも更新」の依頼で使う。
手動編集後のファイルを正本とし、デザイン改善とは別の作業として扱う。

## 保存するもの

削除したページ、表示順、文言、改行、座標、書式、図形、画像、リンク、ノート、
埋め込みフォント・メディアを含めて取り込む。
完全再現の依頼では、残存する表の行・古いページ番号も自動補正しない。
気付いた点を伝える場合も、正本の修正は依頼された範囲に留める。

## 実装方式の選択

- 既存の描画コードで正確に表現できる編集なら、内容と配置のコードを更新する。
- OOXMLの微細な書式まで完全一致が必要なら、PPTXの内部パーツを展開してGit管理し、
  それを再構築する方式が使える。文字・図形をネイティブに保ち、画像化しない。
  この方式への変更はREADMEに明記し、以後どのファイルを編集するかを説明する。
- 構造変更を伴う再編集には、既存の部品単位の編集コードを使う選択肢も残す。
  単に古いスライド群の生成関数へ戻して削除済みページを復活させない。

OOXML方式では、元ファイルのハッシュ・内部パーツ一覧を記録し、
再取込みコマンドと通常ビルドを分ける。通常ビルドは認証情報やDriveへの接続なしで動かす。
パーツのバイトを保つため改行変換を無効にし、バイナリのメタデータも保持する。
スライド順序はファイル名でなくpresentationの参照関係から取得する。

## 「一致」の確認と報告

依頼された再現性の確認では、次の範囲を区別する。

| 比較 | 分かること |
|---|---|
| ページ数・順序・内容 | 削除や並べ替えを取り込めたか |
| 展開した全内部パーツのバイト比較 | 本文以外のノート・フォント・リンク等も保持したか |
| 同じ環境で全ページを描画して画素比較 | その描画環境で外観が一致するか |
| コミット対象だけを別ディレクトリへ展開して生成 | 未追跡ファイルやローカル依存なしで再生成できるか |

ZIPのヘッダーや圧縮によりPPTX全体のハッシュは変わりうる。
全内部パーツの一致と、PPTXファイル全体のバイト一致は区別して報告する。
LibreOfficeでの画素一致を、Google SlidesやPowerPointの表示確認とは呼ばない。
通常の出力PPTXと現行PDF・PNGを同期し、削除ページを含む旧プレビューは旧版と分かる場所へ移す。

ユーザーが編集したDrive版をローカルへ取り込む依頼は、Driveへの上書き依頼ではない。
指定されたリポジトリ・ブランチへ必要な生成元を記録し、他の作業の変更を混ぜない。
