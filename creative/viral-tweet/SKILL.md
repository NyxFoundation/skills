# バズる X（ツイート／スレッド）作成

X のアルゴリズムに最適化し、**リプライ・ブックマーク・滞在時間**を稼ぐ投稿を設計・執筆するスキル。
「いいね」ではなく、**out-of-network（For You）に押し出す信号**を狙う。

## 関連スキル
- **narrative-heat-engineering (NHE)** — 中心の主張（少し尖らせる敵＝構造）と伏線回収を先に決める。
- **emotion-curve-feedback** — スレッドを1ポスト＝1区間として感情曲線を診断し、谷（離脱点）を直す。
- **notion-databases** — 最終ステップの Notion 保存。DB ID は `docs/nyx-directory.md`。

## 設計原則：アルゴリズムが押し出す信号（2024–2026）

**加点（強い順・相対）**: 著者が返信する会話（最大級）＞ リプライ ＞ リツイート ＞ プロフィール訪問→反応 ＞ 会話クリック＋2分以上の滞在 ＞ **ブックマーク（保存・farmしにくく高評価）** ＞ 動画50%視聴 ≫ いいね（ほぼ最弱）。
**減点（乗算・アカウント評価に累積）**: 攻撃的表現（-80%）／**本文への外部リンク（非Premiumは実質ほぼ死ぬ）**／「興味なし」ミュート/ブロック/通報／ALL CAPS・煽り定型文／ハッシュタグ乱用。

**構造的事実**
- **最初の15〜60分の初速が全て**。目安: 5分で3反応→初期ブースト、15分で10→二次、30分で50→拡散。
- **多様性キャップ**: 1フォロワーのFor Youに出る自分の投稿数は限られる。**1日3〜5投稿まで**（多投は各投稿の到達を薄める）。

**設計の一行原則**: いいねでなく **リプライ＋ブックマーク＋滞在** を狙う。全投稿に「返信されるか／保存されるか／2分読まれるか」を問う。

## ワークフロー

### Step 1 — 型を選ぶ（1投稿 = 1アイデア）
| 型 | いつ | 効く信号 |
|---|---|---|
| 単発パンチ（≤280字） | ホットな主張・1行の発見・引用したくなる断言 | 引用RT・ブックマーク |
| スレッド🧵 | 解説・論文/結果の分解・プレイブック | 滞在・ブックマーク |
| リスト（N個） | 保存前提のノウハウ・ツール・失敗集 | ブックマーク（最強の保存磁石） |
| Before/After | ベンチマーク・手法比較（画像と併用） | 引用RT・滞在 |
| 「Nヶ月/N日やった」 | ローンチ・振り返り・build in public | 滞在・信頼 |

研究アカウントは「結果を1行目→図1枚→arXivはリプ」が定石。

### Step 2 — フック（最初の1行）を作る
スクロールは秒速3〜5投稿。**line 1 で好奇心ギャップ**（主題は言う／答えは伏せる）を開く。リンク・ハッシュタグは1行目に置かない。

| # | 型 | テンプレ（JP / EN） |
|---|---|---|
| 1 | 好奇心ギャップ | 「[結果]を10倍にした[X]が1つ。ほぼ誰も使ってない：」 |
| 2 | 逆張り・誰も言わないが | 「みんな[通説]と言う。逆だ。本当に効くのは：」 |
| 3 | 数字/リスト予告 | 「[大きな成果]する[もの]を5つ（保存推奨）：」 |
| 4 | 変化・N日 | 「半年前は〇〇。今は〇〇。やったのは5つだけ：」 |
| 5 | 断言＋証拠 | 「[X]は終わってない。これで先週200万表示。分解する：」 |
| 6 | 損失回避 | 「[X]を知らないと[時間/金]を無駄にしてる：」 |
| 7 | 物語導入 | 「〇〇を辞めかけた。あるメール1通で変わった：」 |
| 8 | インサイダー暴露 | 「[論文/repo]を200本読んだ。90%が同じ3つを言ってる：」 |
| 9 | 構造への名指し批判（研究向き） | 「[分野]のボトルネックは[X]じゃない。[Y]だ。理由：」 |
| 10 | 結果先出し | 「[具体的な数字]を達成した。手法を全部：」 |

**フック規則**: 1アイデアのみ／1行目に具体名詞か数字／「…続きを読む」の折り返しに主張を埋めない。**必ず3案以上**出し1本選ぶ。

### Step 3 — 本文を組む
- **スレッド**: フック（単体で成立し payoff を約束）→ 1ツイート1アイデア → **価値は tweet 1〜3 で先に出す**（8ツイート引っ張らない）→ 最後に CTA。図/チャートは2番目、リンクは最終リプ。
- **単発**: 主張→一言の裏付け／意外性→（任意）問い。280字以内。
- **リスト**: 番号＋1行×N＋「保存してどうぞ」。

### Step 4 — 拡散の仕込み（保存 vs 引用RT）
- **ブックマークされる**＝有用性（実行可能・後で参照したい：リスト/手順/コード/枠組み）。密度と完結性で保存を取る。
- **引用RTされる**＝認知的不協和（反論/賛同したくなる主張）・アイデンティティ表明・感情の強度・当事者性・社会的通貨（シェアで賢く見える）。
- 伸ばすなら**両取り**：保存に値する中身を、少し尖った・アイデンティティを刺激するフレームで包む。返信理由を残す（意見を問う／ギャップを残す）。

### Step 5 — フォーマット
- 長さ: 単発は280字未満で初速最大。改行で1アイデア1行、モバイルの折返し上に主張。
- 絵文字: 機能的に最小限（🧵 → ✅ 等）。フック行には置かない。
- **ハッシュタグ: 効果なし。3個以上は逆効果（0〜1個）**。
- **リンクは本文に置かない** → 最初のリプ or スレ2番目（「リンクはリプに👇」）。
- 画像/図/スクショ = 約2倍のエンゲージ（価値ある図のみ。研究は結果チャート/アーキ図が効く）。
- 投稿時間（JST）: 通勤・昼・夜 ≈ 7〜9時 / 12〜13時 / 21〜23時。夜が強い。

### Step 6 — CTA & 成長ループ
- **保存誘導（弱め）**: 「次の[X]用に保存推奨」。
- **返信プロンプト（最高加点）**: 末尾に問い →**自分の返信者に即レス**（著者返信は最大級加点）。最初の10件に素早く返す＝初速に効く。
- **フォロー訴求**: スレ末尾で価値を出し切ってから「[分野]について書いてます。フォローどうぞ」。
- **自己リプでリンク**: 本文で価値、リプ1で「全文/repo👇」。

### Step 7 — emotion-curve-feedback で自己診断（スレッドは必須）
フック→各ツイート→CTA を1区間ずつスコア化。**谷（引っ張りすぎ/中だるみ）**と**着地（保存・フォローしたくなるか）**を直す。特に tweet 2〜3 で payoff が来ているか。

### Step 8 —（ゴール）Notion Scrapbox DB に保存

## やってはいけない（reach を殺す）
- 本文の外部リンク（特に非Premium）／ハッシュタグ2個以上
- 露骨な engagement-bait（「同意ならRT」「YESと返信」）／ALL CAPS・攻撃・自己宣伝連投
- 1日8〜10投稿（希薄化＋評価低下）／スレで payoff を引っ張りすぎ（離脱→滞在低下）

## 実例（構造）
- 単発・逆張り＋アイデンティティ: 「AI安全性のボトルネックは大きなモデルじゃない。今あるモデルを**形式検証**できないことだ。それが全て。」→ 構造への名指し＋認知的不協和で引用RT。
- リスト・保存磁石: 「論文200本で分かった伸びる研究発信の型5つ：①結果を1行目 ②図は1枚 ③arXivはリプ ④主張は少し尖らす ⑤最後に問い。保存してどうぞ。」

## Notion 保存（ゴール）— Scrapbox DB に PRテンプレで

このスキルの**成果物は必ず** Notion Scrapbox DB に新規ページとして保存する（完了条件）。
API 手順・ブロック追記の gotcha は **notion-databases** スキル、Scrapbox DB ID は **docs/nyx-directory.md** の「Scrapbox DB」を参照（ハードコードしない）。認証は `~/.config/notion/api_key` または `notion` MCP。

**プロパティ**
- `Name`（title）= `[PR原稿] <案件名> / X`
- `Tag`（multi_select）= `["PR原稿", "X", "<案件名>"]`

**本文ブロック（この順）**
1. **callout(💡)** — 一言サマリ＋狙う信号（例:「ブックマーク＋引用RT狙い」）＋想定投稿時間帯
2. **H2 本命** — 単発なら完成ツイート、スレなら各ツイートを番号付きリスト/段落で（コピペで投稿できる形）
3. **H2 バリエーション** — フック違いの別案（Step 2 の3案含む）
4. **H2 バズ設計メモ** — フックの型／保存 or 引用RT の狙い／CTA／自己リプ導線／リンク配置
5. **H2 参考・出典**

> Notion API は1回のページ作成で**100ブロック上限**。超えたら分割し `PATCH /v1/blocks/{id}/children` で追記。MCP 優先、失敗時 curl。保存後、作成ページ URL を返す。
