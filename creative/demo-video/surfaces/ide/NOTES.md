# surface: ide

A code editor (VS Code Dark+) — for editor extensions, LSPs, linters, analyzers, provers, anything whose value appears next to code.

## What to fill in

| Part | What it must say |
|---|---|
| title bar / breadcrumbs / tabs | the real file name and project name |
| explorer | `src/`, the file, and 2–3 `lib/` deps the audience recognizes |
| `#mainPre` | 40–70 lines of *real* code: actual import paths and idioms of that ecosystem |
| diagnostics | 3–4 findings, not ten. Each believable to a practitioner |
| `.side-ed` | the second pane: spec, test, proof, config — whatever the tool reasons against. Delete it if the story has no cross-pane moment |
| `.infoview` blocks `#iv0..#iv2` | waiting → failing → passing |
| status bar | branch, error/warning counts, `Ln x, Col y`, `Spaces: 4`, `UTF-8`, `LF`, language mode |

## Markup rules

- One `<div class="ln">` per line: `<i>N</i><u></u><code>…</code>`. Hand-tag tokens with
  `.k` keyword `.t` type `.f` function `.v` variable `.s` string `.n` number `.c` comment `.ct` control.
- A diagnostic line gets `warn|err|ok|info` + an `id`; `D.lit(id)` reveals it.
  Struck text goes in `.sk`, the squiggled symbol in `.sq`, the message in `.hint` (≤ 45 chars).
- `.lens` and `.peek` must be **siblings of `<code>`**, not children — inside `<code>`
  they inherit `white-space:pre` and their newlines become blank lines.
- Terminal lines are generated by JS (`D.tline`), never hand-written into the HTML.
- A folded region (`⋯` badge on a `›` gutter marker) is a cheap, very real-looking way to
  hide boilerplate like a 14-field struct.

## Surface helpers (on top of the core D.*)

| helper | use |
|---|---|
| `D.renumber(preId, insertId, ±1)` | keep line numbers honest after an inserted line |
| `D.info(n)` | switch the side pane's info block: 0 waiting / 1 failing / 2 passing |
| `D.crossLink(aId, bId)` | dashed connector from a side-pane line to an editor line, routed down the minimap column |
| `D.problems(err, warn)` | PROBLEMS badge + status-bar counters |
| `D.panel('term' \| 'problems')` | switch the bottom panel |
| `D.cls(D.stage,'split')` | slide the second editor pane in |

## Story shape that works

idle → run the tool in the terminal → first easy win (a warning lights up, counter ticks)
→ second pane opens → the real problem, revealed with a cross-pane connector and a peek
→ the fix typed in and re-verified → PROBLEMS tab with the fixed item struck through.

One "wow" per demo — usually the connector plus the auto-applied fix. Everything else stays quiet and correct.
