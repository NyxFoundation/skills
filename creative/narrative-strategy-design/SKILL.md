# Narrative Strategy Design

This skill provides a systematic approach to transforming raw technical updates or organizational changes into strategic narratives that establish a unique "position" in a competitive ecosystem.

## Core Principles

1. **Avoid the "Window" Trap**: Positioning based on geography (e.g., "The Japanese window for X") is a weak position. Positioning based on a **domain void** (e.g., "The only organization handling Industrial Systems for X") is a strong position.
2. **Functional Mapping**: Map the existing ecosystem by "verbs" (e.g., *Build*, *Make Private*, *Bring Institutions*). Identify the missing verb that represents the "next challenge" for the ecosystem.
3. **The Logic Climb**: Structure arguments as a climb:
    - *Current State* $\rightarrow$ *Structural Change* $\rightarrow$ *Emerging Gap* $\rightarrow$ *New Concept (Naming the Gap)* $\rightarrow$ *Solution (Positioning)*.
4. **Concrete Proof Points**: A strategic position is a claim; it requires a "Proof Point" (a real-world project or case study) to transform the claim into a fact.

## Workflow for Positioning Articles

### 1. Ecosystem Mapping
- Identify key players and their primary functions.
- Distill their roles into a single active verb per organization.
- Visualize the matrix: Who covers which layer (Protocol $\rightarrow$ Implementation $\rightarrow$ Adoption) and which axis (Financial $\rightarrow$ Industrial $\rightarrow$ Retail).

### 2. Gap Analysis
- Search for the "missing function."
- Distinguish between a *Geographic Gap* (no one is doing this in Japan) and a *Domain Gap* (no one is doing this for Industrial Systems).
- Prioritize the Domain Gap.

### 3. Concept Synthesis (The "Naming")
- Invent or adapt a technical term to define the gap (e.g., "Ethereum Assurance").
- Define the pillars of this concept (e.g., Correctness, Security, Verifiability, Reliability).
- Position the user's organization as the first/primary "Provider" of this new function.

### 4. Narrative Structuring
Follow the "Logic Climb" structure:
- **Phase 1: Context**. The structural shift (e.g., EF restructuring).
- **Phase 2: Specialization**. Mapping the new specialist organizations.
- **Phase 3: The Pivot**. Identifying the next adoption hurdle (e.g., "From 'it works' to 'it's trustworthy'").
- **Phase 4: Definition**. Introducing the new category/concept (The Assurance Layer).
- **Phase 5: Localization/Implementation**. Why the specific context (e.g., Japan's industrial base) is the ideal proving ground.
- **Phase 6: Declaration**. The organization's new mission statement based on the above logic.

## Pitfalls
- **Over-indexing on Geography**: Avoid phrasing like "The bridge between X and Japan." Instead, use "Solving [Domain Problem] using Japan as the primary implementation field."
- **Generic Terms**: Avoid "Trust" or "Reliability" without a technical definition. Use terms like "Assurance," "Formal Verification," or "Technical Stewardship" to maintain technical authority.
- **Conflict-based Positioning**: Do not position by criticizing existing organizations. Position by identifying a complementary function they *intentionally* left open.
