# Demo Creator

操作と変化で伝わる短い動画を作る。視聴者が次を見たくなる流れを組み、文字はその理解を助ける分だけ残す。
成果物はMP4と編集可能なソース。既存動画の改訂では、ユーザーが直した文言・構成・表示方針を引き継ぐ。

## 最初に決める

1. 対象リポジトリ、デモ名、今回変える範囲を特定する。既存のチェックアウトを優先し、見つからない場合だけ `https://github.com/NyxFoundation/demo-creator.git` を取得する。ローカル配置の一例は `~/workspace/demo-creator`。
2. リポジトリの `README.md`、`docs/scenes.md` と対象デモの台本を読む。新規制作・通常の改訂・3Dの操作手順は [pipeline.md](references/pipeline.md) の該当部分だけ読む。
3. `out/NAME/NAME.yaml` と `examples/NAME/NAME.yaml` のどちらに最新の添削があるか、差分と会話から確かめる。編集済みファイルを雛形で上書きしない。
4. 見せる変化と着地点を一文で定める。各場面に「見せるもの」「新たに分かること」「次に見たくなるもの」を一行ずつ置く。既存の場面数や尺に合わせ、改訂依頼を台本全体の書き直しに広げない。

## 制作の基準

### つなぎを設計する

- 前の場面の結果を、次の場面の出発点にする。同じURL、同じコード、同じユーザーなど、比較に使う視覚的な手がかりを残す。
- 注目点を動かしてから、説明を進める。コード入力・結果表示・新しい字幕を一度に競わせない。
- カット、位置や形の連続、短いクロスフェードを内容に合わせて選ぶ。クロスフェードだけで、話の飛躍は埋まらない。
- 切替時に前の画面を先に消さない。次の画面が準備できるまで保持し、動画の最終フレームも止めてつなぐ。ブラウザとMP4の両方で確認する。
- テンポを上げるときは、重複した説明や修正・再実行の往復から削る。主要な状態が読める時間は残す。

### 文字を選ぶ

- 1場面の主張と、視線を置く場所をそれぞれ一つに絞る。並列ペインは、原因と結果や変更前後を同時に比べる場面に使う。
- 見出しと字幕を同じ説明で埋めない。操作が説明している内容は文字から引く。入らない文はまず削り、意味の区切りで改行する。
- この制作系の標準として、`01 / 08` のような章番号、装飾用の英語小見出し、常駐する細かな脚注は足さない。実際のUIに必要なファイル名・状態表示は残す。
- 出典・取得日・集計条件・保証の詳細は制作ノートへ置く。主張の意味を変える前提は、短い本文か別の説明に残す。
- 技術ノードの内容は、注目した瞬間だけ読める大きさで表示する。細かい名前をグラフ全体に常駐させない。

### コピーを磨く

- 具体的な操作と、起きる結果で語る。短い動詞と自然な語順を選び、名詞の連結、機能の羅列、強い形容詞を減らす。
- エレガントさを、言い切りの明瞭さ、余白、リズムで作る。韻や比喩、煽りを足して飾らない。
- 数字や保証の意味を保って短くする。「CVE報告件数」を「被害件数」に、「ポリシーへの適合」を「何を書いても安全」に置き換えない。
- ユーザーの添削は優先する。事実の誤解を招く箇所は必要な範囲だけ補正し、変更を伝える。
- 台本やコピーを作るとき、またはテンポに迷ったときだけ [copy-and-motion.md](references/copy-and-motion.md) の例と判断基準を読む。

## 組む・見る・直す

1. 主張とコピーを固めてからHTMLを組む。まず静止画で、はみ出し、窮屈な改行、視線の競合を直す。
2. 通し再生で、読み終えた後の待ち、突然の切替、重複した状態を取り除く。`hold` と各型の `timing` を必要な箇所だけ調整する。
3. 3Dは、立体的な関係や動きが理解に役立つ場面に使う。全体の形・ノードの形・カメラ移動を分けて解釈する。「球状の依存関係」は、点群全体の配置として扱う。
4. 3Dは少数の代表フレームを確認してから本番を書き出す。文言だけを差し替える場合は、既存レイヤーの再合成で済むかを調べる。条件は [pipeline.md](references/pipeline.md) を参照する。
5. 完成MP4を通し再生する。HTMLの出来だけで完了にしない。冒頭、接合部、結果、締めの読みやすさと、意図した状態の数を確かめる。
6. MP4、HTMLプレビュー、台本の場所を渡す。3Dを作った場合は `.blend` も残す。保存・公開を依頼された範囲でソースを `examples/` に戻し、生成物と秘密情報をGitへ混ぜない。

## スキルの構成と参照元

ClaudeとCodexで共有するため、共通の `name` / `description` とMarkdownを本体に使う。
操作の詳細は直接リンクした参照へ分け、ホスト固有のUI設定は `agents/openai.yaml` に分離する。
新しいスクリプトを重複実装せず、リポジトリにあるビルド・録画・編集の道具を使う。

設計時に確認した公式文書： [OpenAI — Build skills](https://learn.chatgpt.com/docs/build-skills)、[Claude — Skill authoring best practices](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices)、[Claude Code — Skills](https://code.claude.com/docs/en/skills)。
